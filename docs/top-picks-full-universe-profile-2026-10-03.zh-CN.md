# 完整股票池刷新实测

本报告记录启用跨轮次增量历史之前的全量下载结果。当前脚本运行现有源码，启用
增量历史后的新结果见 [增量历史测试](top-picks-incremental-history-2026-10-03.zh-CN.md)。

## 运行方式

使用现有应用配置、Supabase 股票池、Yahoo 行情下载、原有缺失股票补抓、年度批量
计算器和后台刷新函数，连续运行两轮 `force_refresh=True`，当前优先窗口为 1Y。
未抽样、未模拟价格、未修改下载并发/超时/重试配置、未替换计算公式。

实际股票池为 **699 只股票**，加默认基准 `^AXJO`，批量下载共 **700 个标的**。
配置上限为 1,000，但数据库当前有效股票为 699。每轮由源代码清除本进程行情缓存。

测量脚本 `scripts/profile_top_picks_full.py` 仅用计时包装记录各阶段，使用真实后台线程。
快照写入独立临时目录，不覆盖开发服务的快照，不写入远程数据库。
测试是独立进程内运行生产刷新路径，不包括浏览器渲染、前端轮询等待、应用启动时间，
也不模拟多个浏览器造成的待刷新任务。外部网络、供应商与库内部缓存仍可能影响耗时。

测量终点为四个窗口的新快照全部保存且后台任务退出；同时记录 Year 首先发布的时间。
行情读取总耗时包含批量下载、补抓和底层行情整理/缓存；各窗口计算耗时包含指标计算、
行构造及元数据生成。下载子项已包含在行情读取总耗时内，不能重复相加。

## 数据完整性

两轮均出现：`QUB.AX` 批量下载和补抓都没有返回价格；年度窗口另有 `FDXF`、`HONA`
历史样本不足，按现有规则隐藏年度指标。四个窗口均成功发布，保留原有告警。

| --- | ---: | ---: |

| 首次批量下载 700 个标的 | 273.590 | 278.470 |
| QUB.AX 补抓 | 0.493 | 0.458 |
| 行情读取总计（含上面两项） | 274.202 | 279.038 |
| 1Y 指标/行/元数据生成 | 0.452 | 0.358 |
| 1D 指标/行/元数据生成 | 0.742 | 0.805 |

| 1M 指标/行/元数据生成 | 0.816 | 0.810 |
| 四窗口计算合计 | 2.970 | 2.924 |
| 四次快照保存合计 | 0.320 | 0.472 |
| Year 发布时刻（从本轮开始计时） | 275.012 | 279.971 |
| 四窗口全部发布时刻 | 277.821 | 282.901 |
| 后台任务完成总耗时 | **277.859** | **282.908** |

两轮分别约 **4 分 38 秒、4 分 43 秒**；行情读取占总耗时 **98.68% / 98.63%**。
这次实测确认当前瓶颈是原始行情下载，不是多指标计算或本地快照保存。
只有一次缺失股票重试，且不到半秒，因此本次大部分下载耗时也不是补抓造成的。

页面可能还需等待下一次 20 秒轮询获取已发布快照；若已有上一轮任务，还可能涉及
排队等待。该测试未测这些前端/多请求等待，不能把后台耗时直接等同于每次浏览器更新时间间隔。
