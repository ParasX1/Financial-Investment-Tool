# Top Picks 跨轮次增量行情

## 当前行为

生产服务通过 `TopPicksHistoryProvider` 维护 Top Picks 所需的复权价格历史。
首次无历史时仍按请求窗口下载；后台首次需要一年范围时补齐一年历史。后续刷新：

1. 已覆盖所需范围的股票，下载最近 7 个自然日的重叠行情。
2. 如果中间停止运行过，从上次已覆盖日期往前 7 天开始补抓，避免漏掉停机期间的数据。
3. 合并历史和新行情，同一天的数据更新而不增加重复观测。
4. 使用合并后的完整历史执行现有指标计算，四个窗口仍共享本轮行情。

强制刷新只清理短期行情缓存，不删除有效历史。当前网页通过计算完成通知刷新，详见
[完成通知说明](top-picks-live-updates-2026-10-04.zh-CN.md)。
这是**增量下载与历史合并**，并非指标增量计算，也没有加入无人访问时的后台定时任务。

## 存储与校正

- 历史以逐股票复权价格和覆盖范围存入 SQLite，事务写入；无需新增依赖。
- 默认文件为 `TOP_PICKS_CACHE_PATH` 后追加 `.history.sqlite3`。默认绝对路径对应
  `server/.cache/top-picks-snapshot-cache.json.history.sqlite3`。
- 可设置 `TOP_PICKS_HISTORY_PATH` 指定路径；空字符串表示只保留内存历史。
- 服务重启后按股票从本地历史库恢复，数据库文件需要部署环境持久化才能跨部署复用。
- 新增股票、请求更早历史、历史未初始化时，针对对应股票下载完整请求范围。
- 重叠区间中，最后一个原有价格观测之前的历史价格发生显著变化时，对该股票重新
  获取整个请求范围，避免拼接复权前后不同价格基准。末尾可能尚未收盘的价格正常替换。
- 默认每 7 天进行全量校正，以覆盖重叠窗口外的历史修订。这意味着历史库并不保证
  立即发现所有早期修订；每周校正轮次仍可能达到原来的整年下载耗时。
- 单个股票本轮没有可用价格，保留其磁盘历史，但不把它混入本轮新快照冒充新数据。
  所有股票本轮均不可用时抛出数据源错误，后台保留旧快照。
- 复权校正补抓失败的股票同样不与旧价格基准拼接，使用现有缺失数据告警。
- 历史持久化不可用时记录日志，降级到进程内历史；进程重启后需要重新初始化。

## 历史保留与空间回收（2026-10-04）

- 服务取得完整股票池后、开始下载前，每轮清理一次。按当前最长的 `1Y` 窗口，保留
  一年前同日至本轮结束日期的行情；闰年边界与年度计算使用相同规则。
- 日、周、月请求不会裁掉年度计算所需历史。短窗口首次仍按需下载；已有全年历史时，
  周度校正和复权修订会保留该年度覆盖，避免后续年度请求再次补下载。
- 裁剪同时更新内存和 SQLite 中的价格及覆盖范围。下载返回空或抛出异常时，过期历史
  已先被清理；仍在范围内的旧行情保留，但不作为本轮新结果。
- 移出完整股票池的股票同步从内存和 SQLite 删除，基准包含在保留集合中。普通股票
  子集请求不触发退池删除。有效空池清空历史；股票池查询异常不会触发清空。
- SQLite 使用 `auto_vacuum=FULL`，提交时回收空闲页。原有未启用的数据库首次加载
  新逻辑时执行一次 `VACUUM` 转换，后续每轮不执行完整 `VACUUM`。机制见
  [SQLite 官方说明](https://www.sqlite.org/pragma.html#pragma_auto_vacuum)。
- 每次数据库操作均提交或回滚后立即关闭连接，不依赖垃圾回收释放文件句柄。
- 发布快照时也清理内存中过期旧快照及已被替换的启动缓存，保留各窗口最新结果供
  更新失败时回退。磁盘快照仍只保存各窗口最新结果。

缓存规模由保留日期范围和当前股票池决定，股票池增大时仍会增加，不设固定字节数上限。

本次清理修改通过后端全量 245 项测试和静态错误检查。回归覆盖连续 40 天更新、跨重启
增量复用、失败仍清理、子集请求保护、闰年、真实旧库迁移及物理缩小，以及关闭自动垃圾
回收后仍可立即移动和删除数据库文件。本地 700 标的无网络验证中，缩池至 10 个标的后，
自动回收模式的数据库由 4,333,568 字节缩至 77,824 字节，完整性检查正常；测试临时目录已删除。

清理修改后重新实测完全无历史和快照缓存的 699 只股票加基准：首次全量后端刷新年度结果
34.783 秒可用，四个窗口全部完成 40.266 秒，行情读取总耗时 33.329 秒。此计时不含
进程启动、HTTP 传输和浏览器渲染；所有窗口发布成功，`QUB.AX` 仍无行情并保留告警。
新计时追加在原有 `top-picks-production-96-2026-10-04.json` 的 `retention_cold_runs` 中，
临时快照、历史和 Yahoo 缓存均已删除。该次完全空库计时使用原测速包装，省略一次空库
清理；测速工具现已补上清理方法转发，以覆盖后续已有历史的清理行为。

## 验证

专项测试覆盖按需下载到一年范围扩展、跨轮合并、重启恢复、返回值隔离、缺失日期、
末尾价格修订、新交易日、新增股票、历史修订校正、每周全量校正、停机补齐、
下载失败/恢复、复权校正失败和损坏数据库降级。应用装配测试确认实际服务使用历史提供者。

完整 699 只股票加基准的测试使用 `scripts/profile_top_picks_full.py` 连续运行两轮，
第一轮初始化历史，第二轮使用同一历史库；临时历史库与快照文件均独立于开发服务。
原始记录：`docs/benchmarks/top-picks-incremental-full-universe-2026-10-03.json`。

下载仍使用现有 `threads=False` 配置，每只股票的网络请求等待并没有被本次优化移除。
因此缩短日期范围不等于按比例减少下载时间，也不能据此承诺五秒全股票池刷新。

## 完整股票池实测结果

| 阶段 | 初始化轮 | 增量轮 |
| --- | ---: | ---: |
| 主批次日期范围 | 2025-10-03 至 2026-10-03 | 2026-09-26 至 2026-10-03 |
| 主批次标的数（含基准） | 700 | 699 |
| 主批次日期行数 | 258 | 5 |
| 主批次下载 | 283.176 秒 | 261.467 秒 |
| 行情提供者总耗时（含合并/历史保存/补抓） | 285.569 秒 | 265.092 秒 |
| 四窗口计算合计 | 3.179 秒 | 3.020 秒 |
| 快照保存合计 | 0.326 秒 | 0.477 秒 |
| 整轮完成 | **289.550 秒** | **269.850 秒** |

增量轮成功复用了 699 个标的的历史（698 只股票加基准）。`QUB.AX` 初始化没有返回
价格，因此下一轮仍独立请求完整历史并按原有流程重试，依旧无数据。此处没有重试
冷却或人为跳过该股票。两轮年度有效收益股票数均为 696，短周期均为 698；
所有四个窗口都成功发布，原有缺失/短历史告警保留。

增量轮比初始化轮少约 19.70 秒，约 6.8%；这是一次顺序运行的观察，受网络波动影响，
不能作为稳定提速比例。结论是跨轮历史复用已经生效，但减少传输的日期行数并没有
大幅减少逐标的请求等待。要进一步显著缩短时间，需要另行评估有限并发或批量行情源。

验证：后端全量 197 项测试通过，格式化和应用装配补充后相关 13 项测试再次通过，
静态错误检查通过。实测使用临时历史库，未覆盖开发服务的原有快照或历史库。
